# Gap Analysis (AS-IS vs TO-BE)

## 1. Purpose
This document highlights the specific gaps between the current manual operations (AS-IS) and the proposed platform (TO-BE), outlining the steps required to bridge them.

## 2. Gap Identification

| Process Area | AS-IS State | TO-BE State | Identified Gap | Solution / Action Item |
| :--- | :--- | :--- | :--- | :--- |
| **Inventory Tracking** | Excel spreadsheets updated manually at EOD. | Real-time database updates upon scanning/receipt. | Hardware gap: No scanning devices currently exist in warehouse. | Procurement must purchase 10 barcode scanners; IT to integrate them. |
| **PO Approvals** | Emails sent to managers; high risk of being missed. | Automated system workflow with dashboard alerts. | Process gap: Managers are not used to logging into a system daily. | Change Management: Training sessions for managers on the new approval UI. |
| **Supplier Rating** | Subjective, based on buyer memory/gut feeling. | Objective score based on OTD and defect rates. | Data gap: Historical defect data is not digitized. | Migrate last 6 months of paper logs into the new database to establish baseline. |
| **Bin Location** | Workers memorize where items are stored. | System directs workers to specific Aisle/Rack/Bin. | Setup gap: Physical warehouse does not have standard bin labels. | Operations team must print and apply standard barcode labels to all physical bins prior to Go-Live. |
